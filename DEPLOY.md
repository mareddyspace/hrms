# Putting TimeZ online

Portal on **Vercel** · API on **Render** (free) · files on **Backblaze B2** (free, no card) · database on **Neon** (already set up and seeded).

## 1. Backblaze B2 (file storage)

1. Sign up at **backblaze.com** → choose **B2 Cloud Storage** (no card needed).
2. **Buckets → Create a Bucket**: name like `timez-files-<something unique>`, **Private**, Default Encryption **Enable** → Create.
3. On the bucket card, copy the **Endpoint**, e.g. `s3.us-east-005.backblazeb2.com`.
   - `S3_ENDPOINT_URL` = `https://` + that endpoint → `https://s3.us-east-005.backblazeb2.com`
   - `S3_REGION` = the middle part → `us-east-005`
4. **Application Keys → Add a New Application Key**: name `timez-api`, allow access to **that bucket only**, **Read and Write** → Create.
   Copy right away (the secret is shown once):
   - `keyID` → `S3_ACCESS_KEY_ID`
   - `applicationKey` → `S3_SECRET_ACCESS_KEY`

## 2. Render (the API)

1. Sign in at **render.com** with GitHub. **New → Blueprint** → pick `mareddyspace/hrms` and branch **main** (merge your work into main first; `render.yaml` deploys main).
2. Render reads `render.yaml` and asks for these values:

   | Setting | Value |
   |---|---|
   | `DATABASE_URL` | Neon → your project → **Connect** → pooled connection string (`postgresql://...`). Same as in `backend/.env`. |
   | `CORS_ORIGINS` | `https://<your-app>.vercel.app,http://localhost:5173` |
   | `CORS_ORIGIN_REGEX` | Optional, for Vercel preview links: `^https://<project>-[a-z0-9-]+\.vercel\.app$` (or leave empty) |
   | `S3_ENDPOINT_URL`, `S3_REGION`, `S3_BUCKET`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY` | From step 1 (`S3_BUCKET` = the bucket name) |
   | `OPENROUTER_API_KEY`, `AI_MODEL`, `AI_MODEL_FALLBACKS` | Same as in `backend/.env` (optional; empty = built-in Copilot answers) |

   `JWT_SECRET` is generated by Render. The rest (`APP_ENV=production`, `STORAGE_BACKEND=s3`, `RUN_MIGRATIONS_ON_START=true`, `OTP_DEV_ECHO=false`, Python 3.14, region Singapore) is already in `render.yaml`.
3. Click **Apply** and wait for the deploy (a few minutes). Then open `https://<service>.onrender.com/health` — you should see `"status":"ok","database":"ok"`.
4. Database: migrations run automatically at each start. **Seeding is not needed again** — you already ran `python -m app.seed` against Neon from your PC. (Render's Shell is a paid feature; if you ever need to seed again, run it locally in `backend` with `.\.venv\Scripts\python.exe -m app.seed` while `backend/.env` points at Neon.)

## 3. Vercel (the portal)

1. Vercel → your project → **Settings → Environment Variables** → add `VITE_API_URL` = `https://<service>.onrender.com` (no slash at the end), tick **Production** and **Preview** → Save.
2. **Deployments** → latest → **⋯ → Redeploy** (the address is baked in at build time, so a redeploy is required).
3. Open the portal, press **Fill** on a test account, then **Sign in**.

## Good to know

- **Free plan sleep:** after ~15 minutes without visitors the API sleeps; the next request takes **about 50 seconds**. Later requests are fast.
- **Neon region:** Render runs in Singapore; a Neon project in AWS Singapore (`ap-southeast-1`) keeps the portal quickest.
- **Verification codes:** with `OTP_DEV_ECHO=false`, profile-change codes are not shown on screen. For a pure demo you can set it to `true` in Render → Environment.
- **Before real employees use it:** set `VITE_DEMO_MODE=false` in `.env.production` (hides the test accounts) and change the test passwords.
- Render deploys again on every push to **main**.
